## Reachability

None of the three development packages occurs in plugin Host/browser sourcemap sources or direct plugin imports. Their `dev` classification reflects this project's manifest, **not** all DSH Host deployments.

- HMR [source](https://github.com/DeepSeek-ai/deepseek-harness/blob/ca33fd6843b205e279c7ccb6cb73a472c78f5760/packages/boot/hmr/src/index.ts#L418-L440) compiles configured ignored-globs against filesystem paths; [Forge](https://github.com/DeepSeek-ai/deepseek-harness/blob/ca33fd6843b205e279c7ccb6cb73a472c78f5760/packages/experimental/client-ui-forge/src/layers.ts#L71-L78) compiles configured test/interface globs. Host configuration trust matters; chat ZIP content is not shown reaching these patterns.
- Mocker manual-JavaScript injection and Windows redirect traversal require standalone `mockerPlugin()`/`interceptorPlugin()` Vite WebSocket registration. Project [Node tests](../../vitest.config.ts) and [esbuild phone assembly](../../scripts/build-mobile-test.mjs) do not register these APIs. Upstream explicitly distinguishes Node/Browser Mode from standalone mocker servers. [Backport](https://github.com/vitest-dev/vitest/commit/b825313243dc55757e8d7c0f9e7a792135e13473) escapes generated strings and normalizes Windows separators.
- DSH's installed MCP transport forwards configured custom headers to Streamable HTTP. Cross-origin redirects can leak headers/bodies; stdio is unaffected. [Audited-source OAuth wrappers](https://github.com/DeepSeek-ai/deepseek-harness/blob/ca33fd6843b205e279c7ccb6cb73a472c78f5760/packages/mcp/mcp-client/src/oauth-credentials.ts#L70-L84) specify `redirect:'error'`, but source/npm differ and effectiveness remains untested. [rc.5 npm manifest](https://registry.npmjs.org/%40deepseek-ai%2Fdsh-mcp-client/0.2.2-rc.5) still exact-pins `2.2.0`; rc.5 alone does not establish remediation.
