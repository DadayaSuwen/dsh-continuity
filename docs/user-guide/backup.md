# 备份、恢复与删除范围

[English](backup.en.md) · [导入](import.md) · [记忆](memory.md)

> 当前为 **package v1：原始来源与记忆导出**。Host 导出 / 恢复已有实现和实际检查，自动化手机视口已覆盖下载事件；Android/iOS 系统下载、真实用户导出恢复与整体 MVP 仍未验收。checksum 不等于加密或签名。详见[工程运行证据](../engineering/RUNTIME_EVIDENCE.md)。

## 保存角色备份

1. 选择正确的角色档案 / 故事，读取已保存资料。
2. 在“备份与管理”点“下载完整角色备份”。文件含私密聊天原件和记忆，交由你选择的位置保管。
3. 核对浏览器确实保存了文件；保留原 ZIP、原备份，不手工改字段或摘要。
4. 在删除来源前备份以保留全文。删源后备份仍能保留引文，但会标记缺失来源；相关条目恢复时仅为 unknown、未确认候选，不恢复原始证据或 active 状态。

界面的“完整”只指本插件当前分区的来源与记忆，不是完整 Host 或完整官方对话备份。[当前下载实现](../../src/ui/Panel.tsx)、[Host 导出](../../src/routes.ts)

## v1 包含什么

| 包含                                                                                       | 不包含                                    |
| ------------------------------------------------------------------------------------------ | ----------------------------------------- |
| 当前分区保留的全部 sources、精确原 bytes 的 base64 与预览                                  | 完整正式 DSH Session 日志及未采集的新消息 |
| 已显式采集并保留的 `dsh-session-capture` 原始日志切片                                      | 独立官方附件对象库；原包没有的附件正文    |
| candidate / active / conflict / superseded 等记忆、版本、引文                              | Session bindings、import ledger、采集游标 |
| 删除指纹与原记忆 ID 墓碑、分区 revision、导出时间、checksum；缺源时的 `omitted_source_ids` | 模型凭据、Host 配置、加密或数字签名       |

保留的原始字节总是包含，没有“只导摘要”开关。一个原 ZIP 可含未选中的对话；它们仍随原字节进入备份。备份是明文 JSON / base64，base64 不是加密。

新消息若通过手工 service 或显式启用的批次采集保存为来源，也随备份导出；默认 `batchEveryTurns=0`，不自动采集全部新消息。这些切片与完整 Session 是不同资产。[采集范围](import.md)、[包实现](../../src/migration/package.ts)

## 恢复

1. 在目标 Host 选择明确的目标角色 / 故事与用户归属。
2. 选择 v1 备份。Host 校验 schema、payload SHA-256、原字节摘要及 source ID、分区一致性；从原 bytes 重新生成预览并比对，再检查字面引文与来源说话者 / 证据类型。包内自述的预览不是独立证据。
3. 读取恢复结果。相同 id / 记录复用，同 id 不同内容报冲突；合并目标与备份的删除墓碑，并跳过匹配的已删记录，包括编辑后删除的原记忆 ID，不静默覆盖。
4. 恢复的是来源和记忆，不自动产生原正式 Session 或 bindings。需要正式历史时从原 ZIP 重新导入；只用记忆可新建对话。采集切片重导入仅生成标明来源的纯文本 Session，不重建原生事件流或独立附件库。
5. 已有完整来源的候选仍保持候选，不因恢复自动确认。来源若缺失，必须在可选 `omitted_source_ids` 中明确列出；相关引文保留，但条目恢复为 `source_kind: unknown`、`status: candidate`、`confirmed_at: null`，不进入 active 恢复。
6. 未明确标记的缺源引用、原 bytes / 预览 / 说话者证据不匹配仍报错。检查来源和候选后再继续；显式缺源标记也不补造历史或原件。

当前来源写入与记忆更新不是全包事务；出现错误可能已存部分来源。返回 `memory_count` 是合并后总数，不是新增数；先核对目标数据再重试。[package 实现](../../src/migration/package.ts)

默认 Web 恢复受 Host 上传限额约束；base64 + 预览会令备份大于原件，128 MiB ZIP 不保证它的备份能从 128 MiB 入口恢复。先小样本核验，保留原 ZIP；大包流式处理为 **Planned**。

## checksum 的含义

SHA-256 检测摘要与 payload / 原始字节不匹配，帮助发现传输 / 保存损坏。没有密钥、没有数字签名、没有发送者身份认证；有意修改并重新计算摘要仍可能通过摘要检查。恢复另有原 bytes 重解析和说话者证据校验，但这些也不认证发送者。当前 v1 是明文；未来 schema 转换与加密 / 签名为 **Planned**，Node / 插件升级不代表任意版本自动迁移。

## 各种删除互不替代

| 操作                | 当前效果                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 删除单条 / 全部记忆 | 移除对应分区记忆，记录内容指纹和原 ID 墓碑；原始资产、正式对话保留                                                          |
| 删除原始资产        | 删除插件 source；现有记忆 / 引文、import ledger、正式 Session 与附件保留，插件来源全文消失；后续缺源包恢复降为 unknown 候选 |
| 卸载插件            | 停止并关闭服务，默认保留持久数据                                                                                            |
| 删除正式对话 / 附件 | 当前官方 SessionPersistence / Attachment 缺删除 API，不由 source 删除模拟                                                   |

编辑 / 删除记忆不删除旧日志里的资料快照或模型已回答内容。旧备份恢复尊重目标已有墓碑；全新目标若从未收到删除记录，旧备份本身也不含后来发生的删除。处理完整 Host 数据需区分这些资产，不把插件按钮视为全部数据清除。数据保存在当前连接 Host，手机浏览器不是权威库。
