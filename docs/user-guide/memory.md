# 审阅和使用角色记忆

[English](memory.en.md) · [导入](import.md) · [备份](backup.md)

> 候选、确认、编辑、删除、出处、分区与恢复已有 Host 实现和实际回归证据；当前为工程预览，**整体 MVP 尚未验收**。规则提取不是任意对话理解，接线测试也不是不同真实模型人格与剧情质量的证明。详见[工程运行证据](../engineering/RUNTIME_EVIDENCE.md)。

## 从原文到记忆

1. 选择与导入时相同的角色档案 / 故事，读取已保存记录。导入选择了 leaf 时，正式对话与随后候选提取使用同一分支。
2. 检查候选类型：角色设定、用户明确表达、关系、经历、剧情。展开原始出处，核对来源对话 / 消息、说话者和字面引文。
3. 可信内容选“确认记住”。候选及冲突项在确认前不参与恢复；unknown / inference 先编辑核实。缺失原件的引文不等于重新获得原始证据。
4. 有矛盾时明确选替换；旧 active 变成 superseded。冲突仅按同一 fact key 的不同内容识别，不保证发现全部语义矛盾。
5. 编辑任何记忆后都回到候选，需要重新确认。编辑保留 `memory_id`；对同一来源重提取会复用该记录，而不是覆盖用户修改或增加同 ID 副本。过期版本提示时刷新重读。
6. 不要保留的条目可删单条或此角色全部记忆；来源与正式对话保持不变。删除的内容指纹和原记忆 ID 进入墓碑，供后续重提取与旧备份合并识别删除意图。

[当前面板](../../src/ui/Panel.tsx)与[Host 状态机](../../src/memory/memory.ts)提供以上操作。专用手工新增候选界面为 **Planned**；有出处 proposal 已有 service / route。规则遗漏可以保留原文后补候选，猜测不是已确认事实。

## 记忆意味着什么

- `user` 只来自用户明确表达；助手生成的情节、人物台词和明显故事文本不是现实用户资料。不从模型输出自动推测真人信息；当前规则及说话者检查仍需用户审阅语义。
- `persona / relationship / episodic / story` 属角色或故事参考。确认表示用户选择使用这个描述，不表示验证了现实发生。
- 同一 owner / 稳定助手 / 角色 / 可空故事精确归属，`user` 标签也不跨角色共享。当前名称输入也是身份键，改变它会选择另一分区。
- 规则只提来源默认链或显式所选 leaf 中命中的原句，不自动理解所有章节、提取全部分支或记住每条新消息。
- 默认没有第三方记忆 API 或模型提取调用。可选模型提取、向量库和跨角色共享为 **Planned**；已有按轮次规则采集是下节所述的显式启用功能。

## 采集继续聊天的新消息

已绑定的原生 DSH Session 支持 Host service 手工 `extractSession`，也支持显式配置 `batchEveryTurns` 后在对应轮次结束时批量采集；默认 `0` 关闭。当前面板没有新消息采集的专用按钮，不把 service 功能描述成已交付的手工 UI。

服务读取官方 Session Query 的新增日志事件，以持久游标防止重复处理，把原始事件切片保存为 `dsh-session-capture` 来源，再规则提取用户 / 助手文本。新增条目仍是 candidate / conflict，需审阅确认；没有模型提取调用，也不自动把故事当用户事实。采集来源保留后随 [v1 备份](backup.md)导出；未采集的新消息不因一次角色备份而自动被收录。[采集实现](../../src/plugin.ts)、[格式预检](../../src/migration/preview.ts)

## 继续原故事

读取角色后新建或继续已绑定对话，在“模型服务”和“模型”文本框中填 Host 已配置的值。新建时使用这些值；继续 / 发送时通过官方 `model.select` 应用到 live 或 resumed Agent。仅在输入框中打字还未切换模型。发送消息才使用该服务的模型额度。

官方 factory 创建 / 恢复 Agent，已确认资料注册为 scoped context。恢复按最新用户问题的规则匹配相关性、重要性和时间等排序，并用导入回执把来源对话映射到正式 Session，使 session-scoped 记忆只进入对应会话。它不是完整语义检索或跨角色共享。

恢复有预算；长条目可能整条省略，角色与当前剧情等锚点有优先级。预算按插件资料的 UTF-8 字节保守估算，不是整个模型窗口的精确 token 上限。详情见[记忆模型](../architecture/MEMORY_MODEL.md)与[恢复实现](../../src/recovery/recovery.ts)。

官方日志记录资料快照，未变化时去重；编辑 / 删除后新快照声明替代旧快照，实际官方 compaction 后的更新与去重已有回归验证。原始导入历史与旧事件保持不变。面板简要回复展示已由完整官方 Web E2E 检查覆盖，但这不代表原生主对话导航或真实模型质量已验收。

换模型可共享选中的资料；表达、人格与剧情质量仍需真实模型独立验收。编辑或删除影响后续恢复投影，不会抹掉已记录的对话、旧模型回答或日志快照。

## 删除与保管

删除记忆不删除原始资产或正式 Session。删除记录包含内容指纹与原 `memory_id` 的墓碑；重提取尊重删除，旧备份恢复到保留这些墓碑的分区也不使条目复活。[去重与删除](../../src/memory/memory.ts)、[备份合并](../../src/migration/package.ts)

删除原始资产会保留当前记忆引文与正式对话，但移除插件来源全文。删源后导出的包用 `omitted_source_ids` 明确标注缺失来源；相关条目恢复为 `unknown`、未确认候选，不进入 active 恢复，也不补造原始证据。先[备份](backup.md)再删，以保留原件。

数据保存在当前连接的 DSH Host，不是手机浏览器本地。备份是未加密、未签名的明文；当前官方 Session / 附件删除 API 缺失，插件源删除不代表删除全部聊天数据。
