# 审阅和使用角色记忆

[English](memory.en.md) · [导入](import.md) · [备份](backup.md)

> 候选、确认、编辑、删除、出处与分区已有 Host 实现；当前原生界面 **Experimental / 未验收**。规则提取不是任意对话理解，恢复资料不是不同模型人格一致的证明。

## 从原文到记忆

1. 选择与导入时相同的角色档案 / 故事，读取已保存记录。
2. 检查候选类型：角色设定、用户明确表达、关系、经历、剧情。展开原始出处，核对来源对话 / 消息和字面引文。
3. 可信内容选“确认记住”。候选及冲突项在确认前不参与恢复；unknown/inference 先编辑核实。
4. 有矛盾时明确选替换；旧 active 变成 superseded。冲突仅按同一 fact key 的不同内容识别，不保证发现全部语义矛盾。
5. 编辑任何记忆后重新确认。过期版本提示时刷新重读；当前操作不静默覆盖另一次修改。
6. 不要保留的条目可删单条或此角色全部记忆；来源与正式对话保持不变。

[当前面板](../../src/ui/Panel.tsx)与[Host 状态机](../../src/memory/memory.ts)提供以上操作。专用手工新增候选界面为 **Planned**；有出处 proposal 已有 service/route。规则遗漏可以保留原文后补候选，不能把猜测直接宣传为已确认事实。

## 记忆意味着什么

- `user` 只来自用户明确表达；助手生成的情节、人物台词和明显故事文本不是现实用户资料。不从模型输出推测真人信息。
- `persona / relationship / episodic / story` 属角色或故事参考。确认表示用户选择使用这个描述，不表示验证了现实发生。
- 同一稳定助手 / 角色 / 故事精确归属，`user` 标签也不跨角色共享。当前名称输入也是身份键，改变它会选择另一分区。
- 规则只提来源默认分支中命中的原句；不会自动理解所有章节、提全部分支或跟踪每条新消息。
- 默认没有第三方记忆 API 或模型提取调用。周期提取、可选模型提取、向量库和跨角色共享为 **Planned**。

## 继续原故事

读取角色后新建或继续已绑定对话，显式选 Host 已配置模型并发送消息。官方 factory 创建/恢复 Agent，已确认资料注册为 scoped context；官方日志可追踪快照，未变化时去重。原始导入历史不重写。

恢复有预算；长条目可能整条省略，角色与当前剧情等优先。当前预算按插件资料的 UTF-8 字节保守估算，不是整个模型窗口的精确 token 上限；最新问题的自动相关性联动为 Planned。详情见[记忆模型](../architecture/MEMORY_MODEL.md)。

编辑或删除只改变下一次恢复投影，不会抹掉已记录的对话、旧模型回答或日志快照。换模型可共享选中的资料，但表达和人格一致性需要真实模型独立验收，当前没有通过声明。

## 删除与保管

删除记忆不删除原始资产或正式 Session；相同来源/内容指纹有墓碑去重，编辑前后所有版本统一防复活仍待完善。删除原始资产会保留引文而移除全文，可能令后续包缺失证据。先[备份](backup.md)再删。

数据保存在当前连接的 DSH Host，不是手机浏览器本地。备份未加密、未签名；官方 Session/附件删除 API 当前缺失，插件源删除不代表删除全部聊天数据。
