# 导入自己的对话

[English](import.en.md) · [手机入口](mobile.md) · [记忆审阅](memory.md)

> 当前是可独立安装的工程预览，**整体 MVP 尚未验收**。Host 导入与原生面板已有实际运行证据；合成官方 v3 夹具和自动化手机视口检查不代表真实 App 导出、Android/iOS 实机或真实模型质量已经通过。详见[工程运行证据](../engineering/RUNTIME_EVIDENCE.md)。

## 官方 ZIP 优先

1. 在自己已安装的 DeepSeek App 查看是否提供历史导出。以实际版本的菜单为准；没有导出入口时复制 / 分享文本备用，本文不承诺统一菜单路径。
2. 直接选 ZIP，保持原件不变，不先解压。核对当前连接的 DSH Host、角色 / 故事、保存位置和上传限额。保存位置尚未出现时，在 DSH 主界面选择工作区，再点“刷新保存位置”。
3. 查看解析报告：支持的对话、消息树、分支、附件引用和警告。预览仅在 Host 暂存，尚未保存原始资产或创建正式对话。
4. 勾选支持对话。多分支对话可在原生“导入分支”下拉框中保留官方默认或选择一个 leaf，然后点“保存原始记录并迁移”。提交和随后规则提取使用同一分支。**只选一段也保留整个 ZIP**，其中其他对话可能含私密内容。
5. 对照新增 / 重复 / 失败结果。相同来源、对话与分支再次导入时，可复用回执已核验的正式对话；多对话部分失败不等于全部回滚。
6. 审阅原句记忆候选，核对说话者与出处。确认前不进入角色恢复资料，也不把助手生成的故事当作现实用户事实。

## 保留与转换不同

- 当前官方门禁是 `export_format_version: 3`，其他版本明确报错。
- 默认祖先链跟随 `current_message_id`，缺失 / null / 无命中则取最大 message id；不是“最新 FINISHED 分支”。FINISHED 控制回复是否转换。
- 原 ZIP 保留全部分支和未知内容；正式对话只转换默认链或用户选择的 leaf 祖先链。切换分支不修改保管的原 ZIP，也不自动合并其他分支。
- 图片可能由官方服务规范化保存；非图片缺原正文时只有文件卡 / 元数据。不保证所有附件进入正式对话。
- 未完成回复、模板、撤回轮、未知片段按官方规则排除 / 报告；原件保留不等于所有文本进入模型。
- 原标题 / 时间值留在原件，正式标题可规范化，日期解析到毫秒。未知历史不伪造。

详细依据：[本地预检](../../src/migration/preview.ts)、[提交](../../src/migration/migration.ts)、[分支提取](../../src/memory/memory.ts)、[面板联动](../../src/ui/Panel.tsx)与[固定官方转换](https://github.com/DeepSeek-ai/deepseek-harness/blob/ca33fd6843b205e279c7ccb6cb73a472c78f5760/packages/experimental/deepseek-chat-import/src/conversation.ts#L90-L171)。

## 应急 TXT / Markdown / JSON

复制的文本至少标说话者：

```text
用户：角色：你叫林，沉稳温柔。
助手：我会陪你继续灯塔的故事。
用户：剧情：银钥匙在我手里，下一步寻找船长。
```

未标注部分保留 `unknown`，当前需在原文件修正后重新上传再提交。轮次从用户开始，最多接一条助手回复；应急日期缺失保留 null。该通道是一段线性文本，不恢复树、图片正文、原生工具事件或全部平台字段。通用 JSON 请使用[已定义的 messages 格式](../architecture/MIGRATION_FORMAT.md)，不是任意 JSON 自动兼容。

## 原生 DSH 新消息采集

已绑定的原生 DSH Session 可通过 Host service 的 `extractSession` 手工采集，或显式配置 `batchEveryTurns` 启用按轮次批量采集；默认 `0` 关闭。当前面板没有这项新消息采集的专用按钮，既有导入后的提取是另一条流程。

采集使用官方 Session Query 和持久游标，把新增日志事件切片作为 `dsh-session-capture` 原始来源保存，再从其中用户 / 助手文本提取待审阅候选。非文本事件保留在原始切片，不补造附件正文或缺失历史；采集和规则提取均不调用模型，也不自动确认。

已保留的采集来源随 [v1 备份](backup.md)导出，因此新消息在被显式采集后可以进入来源备份。它仍不是完整 Session 日志备份；重新迁移采集来源只创建标明来源的纯文本对话，不重建原生事件流。依据：[采集服务](../../src/plugin.ts)与[采集格式预检](../../src/migration/preview.ts)。

## 报错与数据范围

默认上传 128 MiB；ZIP 展开总量 512 MiB、单条目 64 MiB、最多 10,000 文件、压缩比 200。预检还校验路径、CRC、UTF-8 和 JSON 深度；ZIP64 / 加密 / 分卷明确报错。Host 一次一个暂存，15 分钟过期；先清除暂存再选下一文件。取消 / 中断后已持久化记录可能仍在，应核对回执再重试。[限额实现](../../src/security/archive.ts)、[暂存路由](../../src/routes.ts)

默认保留原始来源。源删除只移除插件原始资产，不删除官方 Session、附件或现有记忆引文。先[备份](backup.md)再删除；删源后导出的包会明确列出缺失来源，相关引文恢复时仅为 unknown、未确认候选，不恢复原始证据。导入和规则提取没有默认外部模型调用；后续发送对话才使用明确选择的模型服务。
