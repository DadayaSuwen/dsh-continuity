## 1. 入口与共同前提

用户打开自己已连接的 DSH Web，在原生侧边栏使用“迁移与记忆”。插件可独立安装到既有 DSH，使用官方 bundle 机制，不表示 DeepSeek 官方背书；不是独立客户端、浏览器扩展或另一套 Harness。当前 UI **仅中文**，英文文档不表示有英文 UI。

本地构建包在 Host 上安装：

```bash
dsh plugin --profile web add ./dsh-continuity-0.1.0.tgz
```

这是本地安装命令，不是公开 npm 发布。付费 / 外部资源、公开仓库与发布、远端配置均需用户明确同意，本文不执行这些动作。

数据发送到**当前连接的 DSH Host**，不是默认留在手机浏览器。选择已有保存位置和明确的角色档案；同一 owner / 稳定助手 / 角色 / 可空故事标识用于后续读取。首次工作区初始化异步完成，面板会短时自动刷新；列表为空时在主界面选择工作区，再点“刷新保存位置”。

当前界面的角色名称输入实际也是 `character_id`；任意改名会选择另一个分区，不是重命名旧档案。显示名与 opaque id 分离为 **Planned**。[UI 入口](../../src/ui/client.tsx)、[当前面板](../../src/ui/Panel.tsx)

## 2. 官方 ZIP 导入

1. 在已安装的 DeepSeek App 检查是否提供历史导出，以实际版本菜单为准。没有实机证据支持统一路径；没有 ZIP 时复制 / 分享文本备用。
2. 获得 ZIP 后直接选择，不预先解压。核对 Host 去向、角色 / 故事、保存位置和上传限额；上传后由 Host 预检。
3. 阅读对话数量、消息、分支、附件引用和警告。预览不产生正式对话或持久来源，暂存 15 分钟，一次一个文件。
4. 勾选支持对话。多分支时用原生“导入分支”下拉框保留官方默认或选一个 leaf，再保存原始记录并迁移。只选一段仍保留整个原 ZIP。
5. 按结果分别查看新增、重复和失败；部分失败不解释为全部完成。相同来源 / 对话 / 分支的重复导入复用回执已核验的正式 Session。
6. 面板随后对同一默认链或所选 leaf 提取原句记忆候选，先核对出处并审阅。导入和候选提取没有模型调用，也不自动确认。

默认祖先链跟随 `current_message_id`；缺失 / null / 无匹配则取最大 message id，不是“最新 FINISHED 分支”。FINISHED 是回复转换条件。原 ZIP 全分支保留不等于每个分支都进入当前 Session；未完成回复、模板、撤回轮与附件按官方转换规则处理。[导入规则](../architecture/MIGRATION_FORMAT.md)、[提交](../../src/migration/migration.ts)、[分支提取](../../src/memory/memory.ts)

## 3. 复制内容应急导入

1. 没有 ZIP 时复制 / 分享自己的对话，标注 `用户：`、`助手：`，保存 TXT / Markdown，或用[通用 JSON 格式](../architecture/MIGRATION_FORMAT.md)。
2. 未知角色和时间保留未知。先修正未标注说话者再重新上传；当前 unknown role 提交返回错误，不自动猜测。
3. 轮次从用户开始，最多接一条助手回复；工具、图片正文和树结构不在应急保真承诺内。
4. 预检、选择、保存和审阅同官方流程。丢失的原始信息不由插件补造。

## 4. 审阅角色记忆

1. 阅读候选内容、类型、来源消息说话者与字面引文。助手生成的角色台词 / 故事不自动转成现实用户资料。
2. 确认可信候选；unknown / inference 先编辑核实。相同 fact key 的冲突明确选择替换，旧记录变为 superseded；规则不保证发现全部语义冲突。
3. 编辑任何条目会回到候选，需再次确认；读取过期版本时先刷新。编辑保留原 `memory_id`，重提取复用而不覆盖修改或生成同 ID 副本。
4. 删除单条或此角色全部记忆只影响记忆分区，来源和正式对话保留。内容指纹与原 ID 墓碑让重提取和保留墓碑分区的旧备份恢复尊重删除。
5. 查看预算内的恢复资料；未确认、unknown / inference 或别的角色记忆不参与。session-scoped 条目还需匹配正式会话或导入回执中的来源映射。

当前规则不覆盖任意语义；手工有出处 proposal 已有 service / route，专用手工新增 UI 为 **Planned**。没有默认第三方记忆 API 或模型提取。[记忆模型](../architecture/MEMORY_MODEL.md)、[Host 状态机](../../src/memory/memory.ts)

## 5. 新对话或继续对话

1. 选同一角色 / 故事，读取已保存资料。
2. 新建对话使用官方 `agents.create`；继续已绑定对话使用 `agents.resume` 或既有 live Agent。既有 Session 绑定另一个身份时明确报冲突，不覆盖角色归属。
3. 在“模型服务”和“模型”文本框填 Host 已配置值。新建时使用这些值，继续 / 发送时官方 `model.select` 应用到 live / resumed Agent；仅打字未切换。发送消息才使用模型服务额度。
4. 已确认资料作为 scoped context 进入下一次组装，按最新用户问题规则相关性、重要性和时间等排序，并通过回执映射正确的 Session 范围。预算按插件文本 UTF-8 字节保守估算，可能整条省略，不是整个模型窗口精确 token 上限。
5. 官方日志记录快照，未变化时去重；编辑 / 删除后新快照声明替代旧快照，实际官方 compaction 后的更新与去重已有回归。原始历史与旧事件不重写。
6. 面板内简要回复显示已由完整官方 Web E2E 验证。这不代表原生主对话选择 / 列表刷新 / 返回导航已验收，也不是新聊天客户端。角色身份 / 剧情质量仍需真实模型检查，不承诺跨模型逐字一致。
7. 新消息可通过 Host service 手工 `extractSession` 或显式配置 `batchEveryTurns` 批量采集，默认 `0` 关闭；当前无专用面板按钮。官方 Session Query 的新增日志切片保存为 `dsh-session-capture` 来源，再规则提取待审阅候选，没有模型调用或自动确认。

采集来源含被显式捕获的新轮次事件，保留后随备份导出；它不是完整 Session / 附件备份，重导入仅创建标明来源的纯文本 Session。[生命周期与采集](../../src/plugin.ts)、[恢复排序](../../src/recovery/recovery.ts)、[官方 factory](https://github.com/DeepSeek-ai/deepseek-harness/blob/ca33fd6843b205e279c7ccb6cb73a472c78f5760/packages/core/agent/src/index.ts#L412-L445)

## 6. 备份、恢复、删除

先下载角色备份，再做破坏性操作。当前 v1 导出原始来源与记忆：包含保留来源的原 bytes、预览、候选 / 已确认资料、引文、删除墓碑及已采集的新事件切片；不含完整正式 Session、未采集的新消息、独立附件库、bindings、import ledger、采集游标或凭据。保留的原始字节总是包含，没有只导摘要开关。

恢复到明确目标归属，合并而非覆盖。Host 校验 payload 与原 bytes SHA-256，从 raw 重新生成预览并比对，再校验字面引文和来源说话者 / 证据类型。同 ID 不同记录报冲突；目标与备份墓碑共同防止已删原 ID 复活。正式对话可从原 ZIP 重导入或新建，包恢复不重建 bindings。

删除原始资产保留现有记忆引文、正式对话和附件，但移除插件出处全文。缺源备份须用可选 `omitted_source_ids` 明确标记；相关条目恢复为 unknown、未确认候选，不进入 active，不补造原始证据。未标记缺源或证据不匹配仍报错。

checksum 只检测不匹配，无加密 / 签名 / 发送者身份认证。来源写入与记忆更新不是全包事务，错误后核对已有数据再重试。Host 的正式 Session / Attachment 删除 API 当前缺失，插件资产删除不是全部聊天数据清除。[备份范围](../user-guide/backup.md)、[package 实现](../../src/migration/package.ts)

## 7. 可恢复的错误与剩余验收

| 情况                                       | 用户动作                                        | 当前边界                                                    |
| ------------------------------------------ | ----------------------------------------------- | ----------------------------------------------------------- |
| 保存位置尚未出现                           | 在 DSH 主界面选择工作区，点“刷新保存位置”       | 首次初始化异步，不创建另一套工作区服务                      |
| 上传过大 / busy / 暂存过期                 | 清除暂存或选更小文件，重新选择                  | 默认 128 MiB 上传；刷新页面不保证释放 Host 暂存             |
| unsupported version / 坏树 / 缺文件        | 保存原文件，阅读报告，使用已知格式备用          | 未支持版本不强行当 v3                                       |
| unknown role / 顺序错误                    | 给说话者标注并重新上传                          | 不猜历史说话者                                              |
| partial import / workspace mismatch        | 核对已存对话与回执后重试                        | 不自动删除已持久化 Session                                  |
| stale memory / conflict / binding conflict | 刷新、审阅，明确替换或选择正确角色 / 新 Session | 不静默覆盖身份或记忆                                        |
| package digest / source evidence 错误      | 使用原备份，保留原 ZIP，检查明确缺源标记        | 不绕过摘要、预览重解析或说话者检查；缺源只恢复 unknown 候选 |
| 模型服务 / 模型值变更                      | 用 Host 已配置值并继续 / 发送                   | 仅输入不触发切换；真实模型质量另验收                        |

归档默认展开总量 512 MiB、单条目 64 MiB、10,000 文件、压缩比 200；一个 Host 暂存 15 分钟。原来源默认保留；base64 与预览扩大备份，上传限额不等于同体积原件可恢复承诺。[限额](../../src/security/archive.ts)、[路由](../../src/routes.ts)
