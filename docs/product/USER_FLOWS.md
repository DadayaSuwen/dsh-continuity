# 用户流程

[English](USER_FLOWS.en.md) · [主需求](PRD.md) · [手机指南](../user-guide/mobile.md)

> 2026-11-18（Asia/Shanghai）源码快照。Host 主流程已有实现；原生 sidebar UI 正在集成，**Experimental / 未验收**。本页是使用流程与验收目标，不是手机或 live 模型通过记录。

## 1. 入口与共同前提

用户打开自己已连接的 DSH Web，在原生侧边栏使用“迁移与记忆”。插件装入既有 DSH bundle；不提供独立客户端或浏览器扩展。数据发送到**当前连接的 DSH Host**，不是默认留在手机浏览器。选择已有保存位置和明确的角色档案；同一稳定助手 / 角色 / 故事标识用于后续读取。

当前界面的角色名称输入实际也是 `character_id`；任意改名会选择另一个分区，不是重命名旧档案。显示名与 opaque id 分离为 **Planned**。[UI 入口](../../src/ui/client.tsx)、[当前面板](../../src/ui/Panel.tsx)

## 2. 官方 ZIP 导入

1. 在已安装的 DeepSeek App 检查头像、设置或数据管理是否提供历史导出。没有实机证据支持统一菜单路径；版本 / 地区 / 系统可能不同。
2. 获得 ZIP 后直接选择，不预先解压。界面显示 Host 去向和上传限额，上传后在 Host 预检。
3. 阅读对话数量、消息、分支、附件引用和警告；取消不产生正式对话。预览暂存 15 分钟，一次一个文件。
4. 勾选支持的来源对话，核对角色和保存位置，再保存原始记录并迁移。只选一段仍保留整个原 ZIP。
5. 按结果分别查看新增、重复和失败；部分失败不解释为全部完成。重复导入复用账本已核验的正式对话。
6. 提取原句记忆候选，先审阅再继续。导入和候选提取没有默认模型调用。

默认正式对话跟随官方 current 分支，备用 leaf 提交与记忆联动为 **Experimental**。原 ZIP 全分支保留不等于每个分支都进入当前对话。[导入规则](../architecture/MIGRATION_FORMAT.md)

## 3. 复制内容应急导入

1. 没有 ZIP 时复制 / 分享自己的对话，标注 `用户：`、`助手：`，保存 TXT/Markdown，或用[通用 JSON 格式](../architecture/MIGRATION_FORMAT.md)。
2. 未知角色和时间保留未知。先修正未标注说话者再重新上传；当前未知 role 提交返回错误，不自动猜测。
3. 轮次从用户开始，最多接一条助手回复；工具、图片正文和树结构不在应急保真承诺内。
4. 预检、选择、保存和审阅同官方流程。丢失的原始信息不会由插件补造。

## 4. 审阅角色记忆

1. 阅读候选内容、类型和原始出处。角色台词 / 故事内容不转成真人资料。
2. 确认可信候选；unknown/inference 先编辑核实。相同 fact key 的冲突明确选择替换，旧记录失效。
3. 修改已确认内容会回到候选，需要再次确认；读取过期版本时先刷新。
4. 删除单条或此角色全部记忆只影响记忆分区，来源和正式对话保留。
5. 查看预算内的恢复资料；未确认或别的角色记忆不参与。

当前规则不覆盖任意语义，手工有出处 proposal 已有 service/route，专用手工新增 UI 为 **Planned**。[记忆模型](../architecture/MEMORY_MODEL.md)

## 5. 新对话或继续对话

1. 选同一角色 / 故事，读取已保存资料。
2. 新建对话使用官方 `agents.create`；继续已绑定对话使用 `agents.resume` 或既有 live Agent。
3. 显式选择 Host 已配置的模型服务与模型。发送消息才使用模型服务额度；更换输入框值不保证已经活跃的 Agent 自动切换模型。
4. 已确认资料作为 scoped context 随官方日志化快照进入下一次组装；未变化快照去重，原始导入事件不重写。
5. 用角色身份 / 当前剧情检查恢复是否合理。不声称不同模型逐字保持人格；确定性接线与 live 模型体验分别验收。

当前面板内简要回复展示是 Experimental，原生主对话选择 / 列表刷新 / 返回路径仍需 Lead 验收，不是新聊天客户端。[生命周期实现](../../src/plugin.ts)、[官方 factory](https://github.com/DeepSeek-ai/deepseek-harness/blob/ca33fd6843b205e279c7ccb6cb73a472c78f5760/packages/core/agent/src/index.ts#L412-L445)

## 6. 备份、恢复、删除

先下载角色备份，再做破坏性操作。当前 v1 包含原始资产、候选 / 已确认记忆及来源引文；不包含正式 Session、独立附件库、bindings、import ledger 或凭据。恢复到明确目标归属，合并而非覆盖；正式对话可从原 ZIP 重导入或新建。

checksum 只检测内容不匹配，无加密 / 签名 / 身份认证。删除原始资产保留正式对话和记忆引文，但移除出处全文；留有引用的缺源备份可能恢复失败。Host 的正式 Session / attachment 删除 API 当前缺失；插件不把资产删除称为正式对话删除。[备份范围](../user-guide/backup.md)

## 7. 可恢复的错误与剩余验收

| 情况                                  | 用户动作                               | 当前边界                         |
| ------------------------------------- | -------------------------------------- | -------------------------------- |
| 上传过大 / busy / 暂存过期            | 清除暂存或选更小文件，重新选择         | 不声称刷新页面自动释放 Host 暂存 |
| unsupported version / 坏树 / 缺文件   | 保存原文件，阅读报告，使用已知格式备用 | 未支持版本不强行当 v3            |
| unknown role / 顺序错误               | 给说话者标注并重新上传                 | 不猜历史说话者                   |
| partial import / workspace mismatch   | 核对已存对话与回执后重试               | 不自动删除已持久化 Session       |
| stale memory / conflict               | 刷新、审阅、明确替换                   | 不静默覆盖                       |
| package digest / source evidence 错误 | 使用原备份，保留原 ZIP                 | 不绕过摘要或出处检查             |
